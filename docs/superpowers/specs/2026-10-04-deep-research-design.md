# 深度研究（Deep Research）設計

狀態：討論中（2026-10-04）。尚未實作。參考畫面與檔案由擁有者提供（手機與電腦版錄影、範例 PDF、Word、Markdown）。

## 1. 目標

在「+」選單裡加一個新功能「深度研究」：使用者給一個題目，模型先列研究計劃，使用者可在 60 秒內用自然語言修改，之後在伺服器上自主搜尋、閱讀、必要時用 Python 分析與畫圖，最後在同一個聊天視窗裡交出一份有引用的報告，可展開閱讀、跳目錄、下載 Markdown／Word／PDF。

不做的事：
- 不另開頁面或另一個「研究介面」：報告就在聊天視窗裡（卡片 → 展開成全視窗閱讀）。
- 不預先產生檔案：下載當下才用程式產生，不呼叫 AI。
- 第一版不支援 Gemini（它的搜尋是另一套機制）。
- 不標示參考來源（設計參考 ChatGPT，擁有者表示不必標）。

## 2. 已決定

| 項目 | 決定 |
|---|---|
| 模型 | 用目前聊天選的模型 |
| 上限 | 300 次搜尋、1 小時（只算實際研究時間，暫停不算） |
| 計劃倒數 | 60 秒；打字時暫停；修改後重新倒數 60 秒 |
| 終止 | 問「用目前找到的資料寫報告嗎」（寫報告／放棄） |
| 暫停 | 要；做完目前這一輪就停下並存進度；暫停期間可補充指示 |
| 圖表 | 需要時可用 Python 畫，只能用查到且有出處的數字 |
| Python／安全 | 研究時可用 Python；網頁內容不特別當不可信資料處理；只保留看不見的做法（伺服器抓網頁擋內網位址；金鑰與沙盒本來就隔離） |
| 呈現位置 | 聊天視窗裡的報告卡，展開為全視窗閱讀 |
| 入口 | 輸入欄「+」選單，新功能 |
| 固定文字 | 目錄、參考資料、執行摘要等跟著報告語言走，五種語言（zh-TW、en、fr、ru、es） |
| 書籤／目錄 | 依實際標題自動產生，不限數量與層數；PDF 書籤、Word 導覽、閱讀畫面目錄來自同一份標題資料 |
| 引用顏色 | 灰色（Word 超連結樣式改灰，PDF 為灰色圓角標籤） |
| Logo | PDF 第一頁頂端放 Noureon 圓環與名稱 |
| 版面 | PDF 內文 9 pt、A4、邊界約 2.75 cm；Word 內文 12 pt、A4 |
| 卡片下方說明句 | 要有（固定句，五種語言） |

## 3. 互動流程

### 3.1 計劃卡（手機與電腦相同）

- 使用者訊息顯示「深度研究」標籤加題目。
- 回覆先是「處理時間為 N 秒」，然後是計劃卡：標題（「<題目>研究」）、5 條左右的研究項目（虛線圓圈項目符號）、底部三個按鈕：「編輯」、「取消」、「開始」（黑底膠囊，內有倒數圓環與秒數）。
- 倒數歸零自動開始，即使頁面已關閉（倒數時間點存在伺服器，所有分頁、重新整理後秒數一致）。
- 按「編輯」：倒數停止，輸入欄上方出現一個標籤（計劃名稱，可按 ✕ 移除）表示接下來打的字是在修改這份計劃。送出後模型重寫計劃，卡片更新，重新倒數 60 秒。
- 「開始」立刻開始；「取消」結束這次研究。
- 卡片下方有一行固定說明句（已決定：要有）。中文草稿：「深度研究已開始處理「<題目>」。它會先提供研究計劃，接著展開資料蒐集與分析，完成後報告會顯示在這裡。」五種語言各一句。

### 3.2 研究中

- 卡片顯示各項目的進度（進行中的項目有轉圈）、「正在研究…」、即時的「已搜尋 N 次 · 已用時間」、進度條、**暫停**與**停止**按鈕。
- 暫停：做完目前這一輪就停，存進度；繼續時從那裡接。暫停期間可補一句話，下一輪納入。暫停有期限（暫定 24 小時，金鑰暫存期限所限），過了只能停止。
- 停止：問「用目前找到的資料寫一份簡短報告嗎？」；選「寫」就進入寫報告階段，選「放棄」就結束。
- 上限（300 次搜尋或 1 小時）到了：自動進入寫報告階段。

### 3.3 完成

- 統計行：「研究完成時間：13m · 29 個引用 · 158 次搜尋」。
- 報告卡：藍色文件圖示、單行標題、右上「下載」與「展開」；卡內顯示報告開頭（約 400 px，底部漸層淡出，不可在卡內捲動）。
- 訊息按鈕列（複製、重做等）沿用現有的。

### 3.4 全視窗閱讀（同一視窗內取代聊天內容）

電腦版：
- 左上 ✕ 關閉（也可 Esc）。
- 中間一欄文章（約 850 px 寬），標題與章節與下載檔一致。
- 最左邊貼邊有幾條很短的橫線，每條代表一個章節；滑鼠移上去彈出目錄卡片，目前章節黑色粗體、其餘灰色，點了平滑捲動。
- 右上兩個圖示：**下載**（選單：複製內容、匯出 Markdown、匯出 Word、匯出 PDF）、**資料來源與活動**。
- 右側面板：兩個分頁「資料來源」（引用 N 筆，每筆標題粗體＋兩行摘要）與「活動 · 研究時間」（研究過程：思考摘要、搜尋與網站標籤、「工作了 13m 18s」、「完成」、「已產生報告」），右上 ✕ 關閉。
- 引用編號（內文上標灰色小圓）滑鼠移上去彈出卡片：網站 favicon 與網域、標題、摘要；一個標記對應多筆來源時卡片有左右箭頭切換。

手機版：
- 同樣的內容，三個浮動按鈕：**目錄**、**下載**、**活動**（活動面板含資料來源與活動兩個分頁）。
- 目錄是面板，點章節跳轉。

## 4. 伺服器設計

### 4.1 新的執行種類

`server_runs` 新增種類 `research`（`model` 旗標 `{kind:'research'}`，沿用 `{kind:'vision'}` 的做法）。階段：

| 階段 | 做什麼 |
|---|---|
| `planning` | 一次模型呼叫，產出計劃（標題＋項目） |
| `awaiting` | 等使用者開始；`start_at` 存在伺服器，到時自動開始 |
| `researching` | 逐項搜尋、讀網頁、做筆記；可暫停、停止 |
| `writing` | 依筆記逐章節寫報告，最後寫執行摘要 |
| `done` / `stopped` / `failed` | 結束 |

新欄位（需 migration 與 client 可讀欄位授權）：`phase`、`start_at`、`paused`、`active_ms`（實際研究毫秒，不含暫停）。計劃本身放在訊息裡（見 5），執行紀錄只存狀態與計時。

### 4.2 端點

- `POST /v1/research`：建立（含規劃），回傳 runId 與訊息 id。
- `POST /v1/runs/:id/plan`：`{instruction}` 依自然語言重寫計劃，`start_at` 重設為現在加 60 秒。
- `POST /v1/runs/:id/start`、`/pause`、`/resume`。
- `POST /v1/runs/:id/stop`：`{mode: 'report' | 'discard'}`。
- 即時通道沿用 `GET /v1/runs/:id/stream`，事件新增研究專用事件（計劃更新、項目進度、搜尋與網站、統計）。倒數由 `start_at` 推算，所有分頁一致。

### 4.3 研究迴圈

- 新模組 `server/research.js`，重用 `createResearchCalls`（搜尋與讀網頁）、`runSandboxReply`（Python）、`createModelAccess`。
- 每個計劃項目一個小迴圈，目標是該項目；產出短筆記（要點加來源編號），後面階段只帶筆記不帶全文，避免撐爆上下文。
- 寫報告：先依計劃與筆記擬大綱，再逐章節生成（避免單次輸出過長），最後寫執行摘要。引用以 `[n]` 標記，n 對應來源清單。
- 預算：300 次搜尋、1 小時（`active_ms`）。到了就收尾寫報告。
- 暫停、停止都在一輪結束的邊界處理；進度（筆記、已完成項目、搜尋計數、來源）存進度點，沿用現有的重啟接手機制（`server_claim_stale_runs`）。
- 研究期間工具：搜尋、讀網頁、Python。不開其他工具。
- 抓網頁：伺服器端擋掉內網與本機位址。

### 4.4 失敗與重啟

- 部署或重啟時，研究從進度點接手（筆記保留，不從頭來）。
- 暫停中的執行金鑰保留到期限；過期後只能停止。
- 任何階段失敗：卡片顯示原因；已有筆記時提供「用現有資料寫報告」。

## 5. 資料模型

- 計劃卡、進行中卡、報告卡都是訊息的一部分（新的 part 型別），這樣重新整理、換裝置、雲端同步都在。
- `researchPlan`：`{ title, items:[{id,text,state}], startAt, phase }`。
- `researchReport`：`{ title, preview, file, stats:{ms,searches,citations}, sources:[{n,url,title,site,snippet}], toc }`。報告本文存成雲端檔案（沿用 sandbox 檔案的做法：`user-assets/<userId>/<sha256>` 加標記），訊息內只放約 4 KB 的預覽，避免同步的資料量過大。
- 活動紀錄：精簡的步驟清單（上限筆數），存在訊息的執行紀錄區塊（沿用 `noureon-run` 的做法）。
- 雲端同步的訊息附加資料白名單需加入新的鍵。
- 報告本文：Markdown，含表格、數學式（LaTeX）、粗體、引用標記 `[n]`；圖表是圖片檔（標記）。

## 6. 匯出（下載當下才產生）

- 一份固定的「研究報告」模板，AI 不參與。重用現有的文件產生器（PDF、Word、純文字）。
- 標題結構（`#`、`##`、`###`）同時決定：PDF 書籤、Word 標題樣式（導覽窗格與折疊）、閱讀畫面目錄。不限數量與層數。
- **PDF**（依範例量到的規格）：A4；左右邊界約 78 pt；內文 9 pt、章節標題 13.5 pt 粗體、主標題 18 pt 粗體；行距約 13.5 pt；第一頁頂端 logo＋名稱（可點）；頁碼每頁底部置中；引用為灰色圓角小標籤，可點到來源網址；表格標題列下一條線、列間淡分隔線、數字靠右；結尾來源清單（標題＋網址）；檔案資訊含語言、標題、作者「Noureon 深度研究」。
- **Word**：A4；真正的「標題 1／2／3」樣式；內文 12 pt；表格第一列重複、下面一條線；引用為直接連到來源網址的超連結，樣式改灰；數學式為原生公式；嵌入我們的內建字型（Noto Sans 系列，子集化）；結尾來源清單。
- **Markdown**：`#` 標題、表格、公式、`[n]` 引用，結尾「參考資料」清單。
- 按下載 → 按鈕顯示準備中 → 產生 → 存檔。PDF 在瀏覽器端用現有產生器做。

## 8. 分期

1. **引擎**：研究執行（規劃、倒數、修改、開始、暫停、停止、研究迴圈、寫報告、儲存），先配基本的卡片顯示。
2. **介面**：計劃卡、進行中卡、報告卡、全視窗閱讀（目錄、引用卡片、資料來源與活動面板）、手機浮動按鈕。
3. **匯出**：研究報告模板，PDF、Word、Markdown。
4. **進階**：研究中補充指示、圖表。

每期做完回報，推 `main` 等擁有者說「推」。

## 11. 第一期（引擎）實作紀錄（2026-10-04）

已做在 `server/research.js`，由 `server/runs.js` 啟動、`server/app.js` 提供端點（見 `server/README.md`）：

- 沒有新增資料表欄位，也沒有 migration：階段、倒數、暫停、計時都放在「訊息的 `researchPlan` part」與「進度點（checkpoint）」裡；`server_runs` 只多一個 `model` 旗標 `{kind:'research'}`。倒數的開始時間（`startAt`）是伺服器時間，訊息與直播事件都帶 `clock`，直播快照帶 `serverNow`，頁面用差值換算。
- 指令（開始、暫停…）送到「正在執行這個研究的那個程序」的記憶體裡；程序剛重啟、還沒被接手的那幾十秒內會回 404，頁面稍後重試即可。
- 金鑰保留 27 小時、整個研究最長 26 小時、單次暫停最長 24 小時；暫停期限到了以 `pause_expired` 結束，卡片顯示失敗。
- 研究做過進度點的存檔就會把「被接手次數」歸零，所以一天的研究可以撐過多次部署；沒有進度的跳針仍照舊 3 次放棄。
- 計數：每一次搜尋、開網頁、頁內尋找都算一次「搜尋」，上限 300；時間上限 1 小時只算實際研究（暫停、等待倒數不算）。剩下的次數平均分給還沒做的項目（每項至少 8、至多 60 次）。
- 完成時：報告全文（Markdown，上限約 1 MB）直接放在訊息的 `researchReport.text`，另帶標題、執行摘要、來源（只含有被引用的）、目錄（標題）、活動紀錄、統計。**不存雲端檔案**（第二期改的）：模型之後的回合要讀得到整份報告，下載檔案也是在按下載時才由這份文字產生。
- 停止：`{mode:'report'}` 用已完成的項目寫簡短報告（沒有任何完成的項目就直接結束）；其他停止直接結束，卡片顯示「已停止」。
- 還沒做（照分期）：Python 與圖表（第四期）、研究中補充指示（第四期）、匯出（第三期）。

## 12. 第二期（介面）實作紀錄（2026-10-04）

- **模型看得到報告**：送出歷史時，`src/app/ui/research/research-history.js` 把 `researchReport` 轉成一段文字（整份報告＋來源清單），沒寫成報告的研究轉成一行說明；瀏覽器與伺服器共用（`stream-api-call.js`）。
- **入口**：「+」選單新增「深度研究」（圖示 `public/assets/composer-tools/deep-research.png`），選了之後輸入欄出現「深度研究」標籤（跟學習模式一樣會出現在送出的訊息裡）；只對 Gemini、不能呼叫工具的模型、沒有搜尋金鑰、沒登入雲端帳號時，會用通知說明原因，不會啟動。邏輯在 `src/app/runtime/research/research-mode.js`，核心檔案只多了幾行掛勾。
- **送出**：沿用聊天本來的「準備送出」（訊息照常顯示、對話照常存），之後把回覆位置換成研究卡，`POST /v1/research` 交給伺服器；聊天輸入欄馬上可以再用。伺服器接不了時卡片顯示失敗原因。
- **卡片**（`src/app/ui/research/research-card.js`，延遲載入）：計劃卡（倒數圓環以伺服器時間計算，各分頁一致；編輯／取消／開始）、進行中卡（項目狀態、已搜尋次數、已用時間、進度條、暫停／繼續／停止，停止會先問要不要寫簡短報告）、完成卡（統計行、藍色文件圖示、標題、下載選單、展開、約 400 px 高的預覽漸層淡出、卡片下固定說明句）。卡片的內容來自 `research-store.js`，直播事件與訊息都會更新它，以伺服器時間戳較新者為準。
- **編輯計劃**：按卡片的「編輯」→ `hold`（倒數停住），輸入欄上方出現以計劃名稱命名的標籤；之後送出的文字走 `plan`（不產生聊天訊息）；按標籤的 ✕ → `release`（重新倒數）。

## 13. 第三期（匯出）實作紀錄（2026-10-04）

下載當下才產生，不呼叫 AI，也不預先做：卡片與閱讀畫面的「下載」選單有「複製內容、匯出 Markdown、匯出 Word、匯出 PDF」；按下去按鈕顯示「準備中…」，做好後交給瀏覽器（手機需要再點一次時照既有的提示）。

- **同一份模板、同一套產生器**：`src/app/ui/research/research-document.js` 把報告 Markdown 變成既有文件產生器吃的文件（前言放標題、作者「Noureon 深度研究」、日期與設計參數；第一個 `#` 當檔案標題；章節標題全部升一級，所以章節是 Heading 1／2／3；`[n]` 變成指向來源的連結；結尾加「參考資料」清單：編號、標題、網址）。PDF 與 Word 都由 `pdf-file.js`、`docx-file.js` 產生，兩者多了 `context.report` 選項。
- **文件模型**：`buildDocumentModel(content, { citations: true })` 把文字為 `[n]` 的連結讀成引用（`run.cite`），只有報告會開這個選項。
- **PDF**：A4、左右上下邊界 78 pt、內文 9 pt（行高 13.5 pt）、主標題 18 pt、章節標題約 13.5 pt（用設計參數 `bodySize 9`、`typeScale 1.19`、`lineSpacing 1.25` 得到）、字型 Inter＋Noto Sans TC 子集；第一頁頂端 Noureon 圖示與名稱（可點到網站）；頁碼每頁底部置中；引用是灰色小標籤、可點到來源；表格標題列下一條線、列間淡分隔線、全是數字的欄靠右；**書籤對每個標題都有，不限層數**（原本只到三層）；檔案資訊有標題、作者與語言。
- **Word**：A4、內文 12 pt、真正的標題 1／2／3 樣式（導覽窗格可摺疊）、引用是灰色超連結（不加底線）、超連結樣式改灰、表格第一列跨頁重複且下方一條線、數學式是 Word 原生公式、內嵌 Noto Sans 字型子集（瀏覽器內做）。
- **Markdown**：`#` 標題、表格、公式、`[n]` 引用，結尾「參考資料」清單（語言跟報告語言走）。
- **已知差異**：PDF 的灰色引用標籤是方形淡灰底（pdfmake 的文字底色不能做圓角）；Word 沒有 logo 抬頭（規格只要求 PDF）。
- 報告訊息多一個 `finishedAt`（毫秒時間），檔案的日期用它。

## 14. 第四期（研究中補充指令、報告圖表）實作紀錄（2026-10-04）

- **補充指令（steer）**：`POST /v1/runs/:id/steer`，body `{instruction}`。只在「研究中」（含暫停）可用，其他階段回 `wrong_phase`；空白回 `empty`、超過 20 條回 `too_many`（兩者在 HTTP 層是 400 `bad_request`）。每條最多 2000 字，存進檢查點（跟著續跑），計劃卡顯示「已補充 N 條」。之後的每一輪項目研究、大綱、每一章與摘要的提示詞都會附上這些指令；活動紀錄多一種 `steer`。卡片多一個「補充指令」按鈕，輸入框上方出現「補充指令：標題」晶片，送出後不暫停倒數也不重新規劃（與「修改計劃」不同）。
- **圖表**：寫完各章之後多一步（`chartsDone` 記在檢查點，只做一次）。模型只能從「研究筆記裡原樣出現的數字」挑資料，輸出 `SECTION: … CAPTION: … ```chart …````，最多 2 張、每章最多 1 張；`acceptCharts` 會檢查圖表 JSON 合法（沿用聊天室的 `parseAndNormalizeChartSchema`），且圖中每個數值都在筆記裡（筆記的 `[n]` 標號不算），否則整張丟掉。推算值、百分比換算不在筆記裡的就不會畫。失敗只記 `research_charts_failed`，不影響報告。短報告（`short`）略過。
- **呈現**：閱讀畫面用聊天室同一個 SVG 圖表渲染（文章容器加 `model-message` class，圖表 CSS 只對它生效）；PDF 與 Word 走既有文件管線畫圖；Markdown 匯出把圖表區塊改成資料表（不放 JSON）。
- **沒有做 Python**：圖表一律走原生 `chart` 區塊，不開沙盒；若之後需要複雜計算再加。
