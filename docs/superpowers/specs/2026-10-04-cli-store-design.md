# 命令工具商城（CLI Store）設計

狀態：討論完成，等 owner 確認後開始第 1 期。日期：2026-10-04。

## 0. 決定一覽

| 項目 | 決定 |
|---|---|
| 是什麼 | 一個「命令工具」商城：左側欄一個入口，點了跳轉到商城頁。裡面陳列官方（owner 上架）與（之後）使用者上傳的命令工具 |
| 名稱 | 「命令工具」。**與「技能」是兩件事**：命令工具是「可以執行的程式」，技能是「教模型怎麼做一件事的說明與流程」，另有設計，不混在一起 |
| 範例 | OfficeCLI（單一程式檔，內含執行環境，不連網，Apache-2.0）、twitter-cli（Python 套件，要 pip 安裝，要連 x.com，要登入憑證，Apache-2.0）；同組織 public-clis 另有 bilibili、discord、telegram、小紅書等 |
| 加入（＋） | 只在使用者的雲端帳號記一筆「已啟用」，**不下載到裝置**。程式檔在第一次真的用到時才由伺服器取得並快取 |
| 移除（…） | 從清單移除（也有詳細、檢視權限） |
| 更新 | 商城頁有「更新」區，列出有新版的工具，**使用者自己按才更新**，沒有自動更新 |
| 叫用 | 輸入欄打 `@` 跳出選單（版面參考 owner 提供的 ChatGPT 截圖），選了在輸入欄插入晶片，這則訊息就會用該工具 |
| 模型自己用 | 權限頁每個工具有「允許模型自己使用」開關，**預設關閉**（只有 `@` 才用） |
| 執行位置 | 全部在伺服器沙盒（Contabo 日本機器，4 核 8 GB，**x86_64**）。沒登入雲端帳號或伺服器連不上時不能用，並顯示原因 |
| 沙盒網路 | **開放連網**，但每個新網域要詢問：同意這一次／永遠同意／拒絕。工具要裝的東西（pip、npm、下載）第一次用時在沙盒裡自己裝，多等一下可以接受 |
| 事先宣告網域 | **不要求**。作者不必寫會連到哪裡，連的時候才問 |
| 永遠擋的 | 沙盒不能連到伺服器本身與內部網路（127.0.0.0/8、10/8、172.16/12、192.168/16、169.254/16、IPv6 本機與內部位址、容器主機）。這是保護 owner 的機器，不是使用者可調的設定 |
| 對外寫入確認 | **第一版不做**（連到 x.com 本身就已經要同意）。之後覺得需要再加 |
| 不可信處理 | 不對網頁內容做額外防護或限制（owner 決定） |
| 安全憑證 | 原「祕密保管處」改名「安全憑證」。加密存在伺服器，執行工具時才解開放進環境變數；使用者**可以再看到**（顯示／隱藏，同現在 API 金鑰欄位），可替換、刪除 |
| 上傳（第 3 期） | 使用者可上傳自己的命令工具或分享；上傳時 AI 查重與安全審查，**不要太嚴**（三級：擋下、放行加標籤、直接過） |
| 第一版範圍 | 只上官方的；使用者上傳放第 3 期 |
| 待提醒 | 之後把深度研究、學習、搜尋、製作圖像併進同一個 `@` 選單（owner 要求到時提醒） |

## 1. 命令工具包的內容

一個命令工具 = 一份清單檔（manifest）＋程式檔＋使用說明。

清單檔欄位（草案）：
- `id`、`name`、`description`（至少一種語言，其他語言可選填）、`version`、`author`、`license`、`icon`、`category`。
- `artifacts`：每個平台的程式檔，目前只有 `linux-x64`。每個可以是 `{ url, sha256 }`（伺服器從原作者的發布頁下載並檢查雜湊值，不自己存一份）或包內檔案（上傳時存進儲存空間）。
- `install`：第一次使用時在沙盒裡跑的安裝指令（例如 `pip install twitter-cli==x.y.z`）。可以沒有。
- `usage`：給模型看的使用說明（Markdown，有長度上限）。像 OfficeCLI 隨附的 SKILL.md，但這是工具的「怎麼呼叫」，不是技能功能。
- `credentials`：需要的安全憑證，每個 `{ env, label, help }`（環境變數名稱、顯示名稱、怎麼取得）。可以沒有。

不要求寫：會連的網域、哪些指令是寫入。

## 2. 使用者看到的

### 2.1 商城頁
- 左側欄多一個入口「命令工具」，點了跳轉到商城頁。
- 內容：官方工具的卡片（名稱、說明、作者、授權、「＋」）、「我的」清單（已啟用，每個有「…」）、「更新」區。
- 具體版面（卡片樣式、側欄位置與圖示、手機版）**第 1 期開始前要先和 owner 確認**，不先定。

### 2.2 `@` 選單
- 輸入欄打 `@`，輸入文字即時篩選，選單列出已啟用的命令工具（圖示、名稱、右側「命令工具」標籤）。
- 選了之後輸入欄裡出現晶片，跟現在「深度研究」晶片同一套做法。

### 2.3 權限設定頁（設定新增「權限」分頁）
版面參考 owner 提供的 Claude 的「權限」與「網站」頁：
- 上方「網路存取預設設定」：兩個選項——新網站才詢問，已經允許過的不再問（預設）；一律詢問。
- 下方「管理權限」，一列一個、右邊顯示數量：
  - **命令工具**：每個工具一列，點進去有「允許模型自己使用」開關（預設關）。
  - **網站**：用過的網域自動出現在這裡，每個旁邊有「允許／詢問／拒絕」，點了從下方彈出選單，可事後逐個調整。常見下載網站（pypi.org、files.pythonhosted.org、registry.npmjs.org、github.com、raw.githubusercontent.com、objects.githubusercontent.com）**預設允許**，可改。
  - **安全憑證**：每個憑證一列，可新增、顯示／隱藏、替換、刪除。

### 2.4 詢問卡片
- 工具第一次連某個沒有規則的網域時，聊天室跳出卡片：哪個工具、要連哪個網域，三個按鈕「同意這一次」「永遠同意」「拒絕」。
- 「永遠同意」「拒絕」會寫進權限頁的「網站」清單。
- 使用者不在畫面前：伺服器上的工作最多等 **10 分鐘**；回來打開對話會看到卡片，可以馬上回答；逾時當作拒絕，工具顯示「等待授權逾時」。

## 3. 執行

### 3.1 流程
1. 使用者 `@` 了某個工具（或模型自己用，若該工具開了這個選項）。
2. 伺服器確認工具已啟用；第一次用就取得程式檔（下載、檢查 sha256、快取）。同一個版本的快取所有人共用。
3. 起一個沙盒，把程式檔放進去並加入 PATH，把該工具的使用說明放進這次的提示詞。
4. 模型用新的「執行命令」工具跑指令（專用工具，不借 Python 工具，這樣處理時間列能清楚顯示「執行 officecli view …」、輸出與耗時，有停止鈕）。
5. 安全憑證在執行時解開、放進環境變數，模型看不到值。
6. 輸入檔放 `/input`、輸出檔放 `/output`，沿用現有沙盒的檔案卡片與雲端資產存放。

### 3.2 網路
- 沙盒的對外連線一律經過一個過濾代理：查使用者的網站規則（允許／詢問／拒絕）、對「詢問」暫停連線並用即時通道問使用者、永遠擋內部位址、記錄。
- 已知限制：代理適用 HTTP／HTTPS；用自己協定的工具（例如 telegram）可能不適用，第 2 期再評估。
- 沙盒用完即清空，所以 pip／npm 裝的東西下次要重裝。第一版先這樣；若實際太慢，再加「把裝好的結果依版本存起來下次直接用」。

### 3.3 沙盒映像檔要補的
目前 Python 沙盒沒有的：pip、node、npm、git、curl、CA 憑證。這是第 2 期的工作（第 1 期的工具是單一程式檔，不需要）。

### 3.4 其他
- 單次執行有時間、記憶體、輸出大小上限；每位使用者有同時執行數上限（沿用現有沙盒的額度機制）。
- 伺服器重啟時進行中的回覆會從存檔點接續；命令工具可能已執行了一半，**接續時不自動重跑已經執行過的命令**，停下來告訴使用者（沿用 S1 的冪等原則）。

## 4. 資料（草案，第 1 期實作前再定欄位與遷移）

- `cli_catalog`：工具（id、擁有者、官方或社群、狀態、目前版本、清單內容、建立與更新時間）。
- `cli_versions`：每個版本的清單與檔案雜湊。
- `user_cli`：使用者啟用的工具（`enabled`、`allow_model_use`），隨雲端同步。
- `user_net_rules`：使用者的網站規則（網域、規則）。
- `user_credentials`：使用者的安全憑證，加密欄位，主金鑰只放伺服器環境變數（沿用現有金鑰保管處的做法並加上長期保存）。
- 儲存空間：包內檔案放在專用的桶，使用者上傳的放自己的資料夾。
- 所有資料表開啟 RLS，使用者只能讀寫自己的列；官方工具所有人可讀，只有 owner 可寫；「官方」標記只能由伺服器設定。
- 遷移檔放 `supabase/migrations/`，並依 `RELEASING.md` 說明相容與復原。

## 5. 風險與已決定的處理

| 風險 | 處理 |
|---|---|
| 使用者上傳的程式在 owner 的機器上跑 | 沙盒（容器、資源上限、永遠擋內部位址）；第 3 期加 AI 審查（只是第一道門檻，真正的保護是沙盒）；更新版本要重新審查，避免先過審再換成惡意版本 |
| 工具被偷換 | 程式檔用 `sha256` 固定，下載時檢查 |
| 從 owner 的 IP 發出濫用流量 | 單次執行時間上限、每人額度、記錄；需要時可以對網域設全域黑名單 |
| 憑證外洩 | 加密存放、只在執行時解開、只走 HTTPS；使用者可隨時刪除 |
| twitter-cli 這類（現實風險，標在工具卡片上，不擋） | X 的服務條款不允許自動化存取，帳號可能被限制；資料中心 IP 常被擋，不保證可用；twitter-cli 支援 `TWITTER_PROXY`，之後可讓使用者填 |

## 9. 第 1 期實作紀錄（2026-10-04）

**可用與「即將推出」**：目錄在 `src/data/cli-catalog.js`（客戶端與伺服器共用）。八個官方工具都上架，但只有不需要網路、程式是單一檔案的兩個 `ready`：

| 工具 | 狀態 | 說明 |
|---|---|---|
| OfficeCLI 1.0.153 | 可用 | 單一執行檔，來自官方 release；需要環境變數 `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`、`OFFICECLI_SKIP_UPDATE=1`、`OFFICECLI_NO_AUTO_RESIDENT=1`（容器裡沒有 ICU，也不能自己更新）。本機已驗證可執行；容器內（noexec、唯讀）尚未實測，要用 `smoke-test.sh` 驗。 |
| FFmpeg 7.0.2 | 可用 | FFmpeg 官方 repo 只有原始碼、沒有執行檔，所以用 `eugeneware/ffmpeg-static` 的靜態編譯（GPL-3.0-or-later，單一檔，沒有 ffprobe）。 |
| yt-dlp | 即將推出（需要網路） | 用官方的單檔 Python 程式（zipapp，用沙盒的 Python 跑）；Linux 單檔版會自己解壓到不能執行的資料夾，所以不用。 |
| twitter-cli、rdt-cli | 即將推出（網路＋憑證） | pip 套件；rdt-cli 只支援從瀏覽器讀 cookie 登入，伺服器上要靠第 2 期的安全憑證另外想辦法。 |
| csvkit | 即將推出（需要網路） | pip 套件（2.2.0）。 |
| Pandoc | 即將推出 | 官方 release 是 `.tar.gz` 壓縮檔（程式很大），商城目前只收單一檔案；要先補「解壓縮」才能上，下載位址與雜湊屆時再定。 |
| SoX 14.4.2 | 即將推出 | SourceForge 官方只有原始碼與 Windows／macOS 版，沒有 Linux 執行檔；要自己編譯，且 SourceForge 不在下載白名單內。 |

「即將推出」的工具列在商城、不能加入、不能被 `@`，伺服器的 `validateRunSpec` 也會拒絕（只收 `ready` 的工具）。

**程式檔由沙盒主機（runner）下載，不是 Zeabur 伺服器**：伺服器把 `{id, file, url, sha256, size}` 交給 runner（`POST /v1/sessions/:id/cli`），runner 只用 https 從白名單網域（GitHub，每一次轉址都檢查）下載，大小與 sha256 不符就拒絕，依雜湊快取在 `cli-cache/`，再硬連結進該 session 的資料夾，容器以唯讀掛載成 `/opt/cli`。`/tmp`、`/work` 仍是 noexec：只有這些程式能執行，模型寫的檔案不能。

**執行命令**：模型多一個工具 `run_command`（`command`、`note`、`title`、`timeout_seconds`，預設 60 秒、最多 120 秒），在 `/output` 以 `sh -c` 執行，`PATH` 前面加上 `/opt/cli`，環境變數不得改 `PATH`/`HOME`/`LD_*`/`PYTHON*`，結束後整個 process group 都清掉；非 0 結束碼視為錯誤。有 CLI 時一則回覆最多 25 步（原本 10）。只有伺服器上的回覆有這個工具，所以選了命令工具就強制走伺服器的進階路徑；沒登入雲端或關了伺服器回覆時會用通知說明。

**設定**：`cliEnabledIds`（已加入）、`cliModelUseIds`（允許模型自己使用，預設關）、`cliVersions`（加入時的版本，與目錄版本不同就出現在「更新」）；都隨雲端設定同步。

**介面**：左側欄入口「命令工具」（其他語言「CLI」）；商城頁是全視窗頁面（全部／我的／更新、搜尋、列表式卡片、＋／已加入／…／更新／「即將推出」，手機上「…」選單是底部面板）；網址是 `noureon.com/cli`（開啟時加進瀏覽器歷史，上一頁會關閉，重新整理或分享連結會直接開啟；`vercel.json` 有對應的 rewrite）；每個工具用專案自己的 logo（GitHub 擁有者頭像，載不到時換回終端機圖示；由個人擁有的專案不用，免得顯示個人照片）；輸入欄 `@` 選單與晶片。

**未做**：容器內實測（需 owner 在 Contabo 重新部署 runner 並跑 `smoke-test.sh`）、網路與權限（第 2 期）、使用者上傳（第 3 期）。
