# 測驗卡（quiz card）與官方技能 `quiz-maker`：設計

2026-10-09，與 owner 討論後的決定。狀態：設計已定，**尚未實作**；下一步是 owner 看過 `quiz-maker` 技能草稿，再從階段 Q1 開始。

## 1. 要做什麼

模型可以出測驗。選擇題（單選、多選、是非）在聊天室裡變成**互動的測驗卡**；填充題、簡答題、申論題沒辦法自動批改，維持**純文字**，後面附參考答案與評分要點。使用者要求「純文字版」時，全部（包含選擇題）都用純文字。

## 2. owner 的決定

- 卡片（B）和純文字（A）都要，由模型依題型分流；一則回覆可以兩種混著。
- 作答前什麼都不顯示（答案不能提前露出）。作答後，不論對錯，都會看到正確答案、所選選項的說明和補充知識：
  - 答對：先顯示正確選項的說明和**補充說明**，其他選項要按「看其他選項為什麼不對」才展開。
  - 答錯：顯示**每個選項的說明**（包含正確的那個），接著顯示**補充說明**。
- 學習模式要整合；結果按鈕叫**「傳送結果」**。
- 下載格式：Word、PDF、Excel、CSV、JSON；分「考卷版」（只有題目）和「解答版」（答案與每個選項的說明）。
- **分數要存，用 A**：存在對話裡（隨對話同步），不新增資料表；之後若要跨對話的學習紀錄（錯題本）另外排。臨時對話不存。
- 參考 NotebookLM 的做法（提示、解釋、放大、題數與難度由技能處理），樣式保持黑白極簡。

## 3. 卡片行為

- 一次一題。頂端是**分段進度條**（5 題就是 5 段；完成時變成綠與紅）。
- 先選（選項變黑框）再按「確認」；確認後卡片底部長出**結果帶**（答對淡綠、答錯淡紅），帶上是結果、說明和「下一題」「解釋」。
- 右上角：「提示」（作答前、有 hint 才顯示）、「放大」（接全視窗閱讀）、「…」選單（傳送結果、下載）。
- 完成畫面：分數、答錯的題目、「只重做答錯的」「全部重來」「傳送結果」「下載」。
- 「解釋」與「傳送結果」都是把一句話送進聊天室，讓模型回答（學習模式開啟時才有「傳送結果」）。
- 鍵盤：A 到 D 選答案、Enter 確認（桌面）。
- 多選題第一版**全對才得分**（必須剛好選對那一組），之後再考慮部分給分。
- 選項順序可以在每次重來時打亂（卡片依選項本身對應答案，打亂後答案不會錯位）（所以技能規定不寫「以上皆是」這類依賴順序的選項）。

## 4. 資料格式（模型寫的 ` ```quiz ` 區塊，只放 JSON）

```
{ "title": "...", "questions": [ { "type": "single|multi|truefalse", "question": "...",
  "options": [ { "text": "...", "why": "..." } ], "answer": 1 或 [0,2],
  "explanation": "答對後顯示的補充說明", "hint": "可有可無" } ] }
```
限制：1 到 30 題、每題 2 到 6 個選項、是非題剛好 2 個選項、`answer` 從 0 算起；字串是純文字。格式有誤時卡片顯示「題目格式有問題」並把原文當程式碼顯示，不會壞掉；區塊還在串流（JSON 不完整）時顯示「準備中」。

渲染方式和 `skill-draft` 區塊相同：`markdown-rendering-helpers.js` 把 `pre>code.language-quiz` 換成占位 `div.quiz-card`，卡片在看到占位時才**延遲載入**（頁面主要 JS 區塊 gzip 153.4 KB／上限 155、主要 CSS 229.5／230 都幾乎滿了，所以樣式放自己的檔案、跟著卡片載入）。

### 前端要負責的事（模型只寫 JSON，不負責這些）
辨識與驗證 `quiz` 區塊、畫出可點的選項、控制答案何時顯示、算分數與進度、打亂題目與選項並正確對應答案、處理多選的全對計分、下載。**技能要等這些都做完才加進目錄**；技能本身也寫了後備規則：使用者要求純文字、看到原始 JSON、或對話說明卡片不可用時，改用純文字（答案與解析放在最後另一節），不宣稱有計分或下載，不顯示原始 JSON。

## 5. 存分數（A）

每個測驗區塊的作答（每題選了什麼、現在做到第幾題、是否完成、分數）存在**該則訊息的資料**裡，隨對話同步，重新打開對話或換裝置都看得到，沒做完的可以接著做。實作前要對照「分開儲存」（split storage）的訊息結構決定欄位位置與同步方式；臨時對話（`isTemporary` 或 `retentionMode==='ephemeral'`）不存。隱私說明（`PRIVACY.md` 與五語言隱私文字）要補一句，`tests/i18n-data.test.js` 的雜湊要重算。

## 6. 學習模式整合

學習模式（`isLearningMode`，提示詞在 `learning-mode-prompt.js`，延遲載入）規定每個回覆是一段流暢的講解並以探索問題結尾。整合方式：
1. 導師講完一個概念，可以附 1 到 3 題小測驗（取代或補充結尾的開放式問題）。
2. 答錯時每個選項的說明就是鷹架：幫使用者看出是哪個觀念錯了。
3. 「傳送結果」把結果送進聊天室，導師依結果決定下一步（補弱點、換難度）。
4. 學習模式的提示詞要加一小段說明小測驗可以用、什麼時候用，並寫明這是「每個回覆是一段流暢文字」的例外，避免兩邊規則衝突。
學習模式目前不能和多模型會議同時開、不支援進階模式，這些不變。

## 7. 下載

從卡片「…」選單直接下載，檔案由頁面用現有產生器（Word、PDF、Excel）從卡片的題目資料做出，不經過模型：考卷版、解答版、Excel、CSV、JSON（可貼回聊天室再做成卡片）。

## 8. 設計參考

外面的設計網站（Duolingo、Quizlet、Brilliant、Kahoot、Khan Academy、NotebookLM）在這個環境被網路政策擋住，沒有直接看到畫面，是根據搜尋到的文字資料與對這些產品的了解來做的；owner 若提供參考截圖，以截圖為準。借用的手法：Duolingo 的「確認」與底部結果帶、可按壓的選項（底邊較粗）、分段進度條；Quizlet 的鍵帽提示；NotebookLM 的提示、解釋、放大、完成後只重做答錯的；Apple 與 Notion 的克制（白底細邊、靠字級與粗細拉層次）。草稿樣式與在真實程式裡渲染的腳本放在 `quiz-card-drafts/`：`quiz-card-draft-v3.css`（只用 `tokens.css` 的色名）、`render-in-app.mjs`（把卡片放進建置好的程式截圖）。**這是第三版草稿，owner 尚未確認樣式。**

## 12. Q2 實作紀錄（2026-10-09）：存分數（A）

- **存在哪裡：** 訊息的 `metadata.quiz`，每個測驗區塊一筆（鍵是區塊內容的雜湊），內容是答題引擎的 `state()`（哪一輪、第幾題、每題選了什麼、對錯、選項順序）。**不新增資料表**；跟著訊息存進本機，雲端同步時也跟著（`cloud-sync-v2-codecs.js` 的 `KEPT_MESSAGE_METADATA` 加了 `quiz`，單一訊息的 metadata 上限 20,000 字元；每筆記錄超過 8,000 字或同一則訊息加起來超過 16,000 字就不存，只留在頁面）。訊息的畫面簽章（`messageViewSignature`）本來就不含 metadata，所以存作答不會讓訊息重畫。
- **`src/app/runtime/quiz/quiz-store.js`**：`createQuizStores({ memory, getActiveConversation, saveAppData })` 回傳 `storeFor(element)`：卡片所在的訊息（`[data-message-index]` 的 `__astraRenderedMessage`）用物件或 id 對到目前對話自己的那則訊息，寫在它的 `metadata.quiz` 並更新對話的 `lastUpdatedAt`，400 毫秒內的多次點擊合併成一次 `saveAppData()`。**臨時對話**（`isTemporary` 或 `retentionMode==='ephemeral'`）、不在目前對話裡的訊息、不在訊息裡的卡片，只留在頁面的記憶體。訊息還沒掛上頁面時回傳 `null`，卡片先不畫，`quiz-watch.js` 隔 80 毫秒再試（最多 6 次）。
- **重新打開對話或換裝置：** 卡片還原到離開時的位置（做到第幾題、已答的題目、分數、選項順序不變），沒做完的可以接著做；做完的顯示完成畫面。
- **隱私：** `PRIVACY.md` 與五語言的隱私政策文字各加一句（作答和分數跟著訊息保存、雲端同步時也在使用者自己的帳號、除非按按鈕送出結果否則不會送給任何 AI、臨時對話只在頁面開著時記得）；`tests/i18n-data.test.js` 的雜湊已重算。
- **測試：** `quiz-store`（8 項：存在訊息上並合併儲存、重新打開還原並接著做、同一則訊息的兩份測驗分開、臨時對話與不在對話裡的訊息不存、訊息還沒掛上就等、記錄太大不存、用 id 找對話自己的那則訊息、看門員等到訊息掛上才畫卡片）、`cloud-sync-v2-codecs`（`quiz` 一起往返）。
